# Slime Miner 무료 공개 이벤트 쿠폰

원본: `docs/slime-miner/coupons/feed.json`.
익명 HTTPS: https://devnest25.github.io/devnest-policies/slime-miner/coupons/feed.json
기존 Pages의 main `/docs`를 사용한다. 초기 목록은 유효한 빈 목록이며 실제 코드·보상·기간을 지정하지 않았다. 테스트 쿠폰은 게임 저장소의 격리 fixture에서만 사용한다.

## 계약과 코드 생성

UTF-8 JSON `schema_version:1`, `items` 배열(최대100항목/전체262144바이트). 항목은 `id`, `code`, `starts_at`, `expires_at`, `reward:{currency,amount}`를 갖는다.
ID는 영문·숫자·`-`·`_` 1~64자. 코드는 **대문자 영문·숫자·`-`·`_` 1~64자**이며 공백 없이 게시한다. 운영자가 이벤트를 확정한 뒤 새 고유 ID와 새 코드를 생성한다. 생성 규칙은 승인 이벤트 식별자와 순번을 이 문자 집합으로 조합하되 전체 Git 이력의 기존 ID/정규화 코드와 중복되지 않게 하는 것이다. 임의 테스트 코드는 이 공개 원본에 넣지 않는다.
시각은 유효한 UTC `YYYY-MM-DDTHH:MM:SSZ`, 시작 < 종료이며 시작 포함·종료 제외다.
통화는 `minerals`/`ether`만 허용한다. 수량은 양수 십진 정수 **문자열**(최대36자리), 선행0·부호·소수·지수·쉼표·공백 금지다. 제품 LargeNumber 정밀도로 정확히 왕복할 수 없는 수량은 거부한다. JSON 숫자로 게시하지 않는다.
ID와 코드는 영구 재사용하지 않는다. 게시 후 보상·기간 변경은 **새 ID와 새 코드**로 한다. 항목 하나라도 잘못되면 전체 응답이 지급에 사용되지 않는다.

## 게시·검증·롤백

1. 실제 이벤트 코드·보상·기간을 운영자가 확정한다. 전용 브랜치에서 이 파일만 수정하고 전체 Git 이력의 ID/코드 재사용을 검토한다. 기존 우편·공지·업데이트 JSON과 앱/스토어 버전을 변경하지 않는다.
2. 게임 저장소의 `tools/verification/validate_event_coupon_feed.gd`로 후보 원본을 검증한다. Godot4.7 `--headless --path <게임> --script res://tools/verification/validate_event_coupon_feed.gd -- <후보파일>`을 사용한다.
3. PR에서 승인된 코드·통화·수량·UTC 기간과 파서 결과를 검토하고 main에 병합한다. Pages 배포 성공을 확인한다.
4. HTTPS 주소를 인증 없이 GET하여200/본문을 확인하고 게임의 `mvp115_public_https.gd`로 실제 제품 클라이언트/파서를 실행한다. 최초 빈 목록 확인에만 `-- --expect-empty`를 사용한다. 게시 SHA·확인 시각·결과를 남긴다.
5. 문제 시 PR로 마지막 안전한 목록 또는 빈 목록으로 롤백한다. 이전 코드를 복원할 때 과거 이벤트 재노출을 확인한다. 변경 이벤트는 새 ID·코드를 사용한다. 지급한 보상은 회수하지 않는다.

## 공개 구조와 한계

**이 JSON과 Git 이력은 공개되며 모든 코드가 노출된다. 비밀 코드 보호를 보장하지 않는다.** 전체 대상 무료 이벤트 전용이다. 서버·DB·인증·선착순·개인별 코드·유료 지급·기기간 수령 원장은 없다.
기기 로컬 수령 ID는 정상 이용 중 반복 지급을 막지만 재설치·다른 기기·과거 저장 복원에 따른 재수령과 기기 시각 조작은 허용된 한계다. 서버 수준 중복 방지를 보장하지 않는다.
등록마다 새 비동기 조회를 하고 실패 시 캐시로 지급하지 않는다. Pages/CDN 캐시 지연으로 즉시 변경/철회를 보장할 수 없다. 목록에서 삭제해도 로컬 수령 기록은 지우지 않는다.
